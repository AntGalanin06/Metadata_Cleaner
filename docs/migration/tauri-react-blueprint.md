# План миграции на Python 3.14 + Tauri/React

## Цели
- Перевести backend на Python 3.14 с сохранением функциональности очистки и CLI.
- Заменить Flet-интерфейс на современное десктопное приложение на базе **Tauri + React**.
- Улучшить кроссплатформенную сборку, особенно для Linux (минимум системных зависимостей, стабильные пайплайны).
- Подготовить архитектуру, пригодную для дальнейшего расширения (новые форматы, профили, интеграции).

## Предлагаемая архитектура

### Слои приложения
1. **Core backend (Python 3.14)**  
   - Пакет `metadata_cleaner_core` (выделяется из текущего `metadata_cleaner`):
     - Логика обработки файлов (`handlers`, `dispatcher`, `metadata_registry`) адаптируется для использования без UI-зависимостей.
     - Сервис настроек переписывается в API-вид: хранение/валидация в Python, экспорт JSON-схем для клиента.
   - REST API на **FastAPI** (или альтернативе на основе `uvicorn`):
     - Эндпоинты: управление очередью файлов, старт очистки, получение статуса/прогресса, управление настройками, просмотр логов/результатов.
     - Асинхронная обработка, очередь задач, события о прогрессе через WebSocket (поддержка realtime в UI).
   - CLI переиспользует core через FastAPI-клиент или прямой вызов.

2. **Desktop shell (Tauri)**  
   - Rust-команда Tauri отвечает за запуск Python backend-а как фонового процесса (через `tauri-plugin-shell` или кастомное управление).
   - IPC:
     - HTTP/WS запросы из React к локальному FastAPI.
     - Вспомогательные Tauri-команды для системных операций (селектор директорий, drag&drop, доступ к файлам).
   - Управление жизненным циклом Python-процесса (старт/останов при запуске/закрытии приложения, мониторинг ошибок).

3. **React UI**  
   - `apps/desktop` (Vite + TypeScript + React).
   - UI-компоненты: дашборд файлов, прогресс, статистика, детальные результаты, настройки с локализацией.
   - State management через Zustand или Redux Toolkit; запросы через React Query.
   - Сохранение полнофункциональности Flet UI: drag&drop файлов, пакетная обработка, детальные отчёты, уведомления.

### Потоки данных
1. Пользователь выбирает файлы → React отправляет список в backend (POST `/jobs`).
2. Backend ставит задачи в очередь, начинает обработку, транслирует прогресс (WebSocket `/ws/jobs/{id}`).
3. По завершении → React обновляет UI, показывает статистику и детальные логи (`GET /jobs/{id}`).
4. Настройки: React загружает/обновляет конфигурацию через `/settings` (REST); backend синхронно пишет на диск.

### Хранение настроек и результатов
- Backend хранит JSON-конфигурации и логи обработки в `${APPDATA}/MetadataCleaner` (платформозависимо).
- Предоставляет REST/WS для чтения/обновления; клиент не работает с файлами напрямую.

## Шаги миграции

1. **Подготовка backend-а**
   - Выделить чистое ядро (`metadata_cleaner_core`), убрать прямые зависимости от Flet.
   - Обновить `pyproject.toml`/`poetry.lock` до Python `>=3.14,<3.15`.
   - Переписать сервис настроек, добавить pydantic-схемы для сериализации.
   - Настроить тесты под новое расположение модулей, обеспечить 100% сохранение функциональности.

2. **Создание API-слоя**
   - Добавить FastAPI-приложение (`backend/app/main.py`) с маршрутами:
     - `POST /jobs` — создание пакета файлов.
     - `POST /jobs/{id}/start` — запуск обработки.
     - `GET /jobs/{id}` — статусы, результаты, ошибки.
     - `GET /jobs/{id}/logs` — журнал операций.
     - `GET/PUT /settings` — работа с настройками и профилями очистки.
   - Реализовать очередь обработки (asyncio + background tasks).
   - Обеспечить тестирование API (pytest + httpx).

3. **Инфраструктура сборки backend-а**
   - Создать `backend/Dockerfile` для повторяемых билдов и CI (особенно Linux).
   - Добавить make-цели/скрипты для генерации wheel/standalone-дистрибутива.
   - Настроить GitHub Actions (lint/test/build) для Python 3.14.

4. **Tauri + React**
   - Сгенерировать Tauri-проект (`apps/desktop`) с Vite/React.
   - Настроить ESLint/Prettier/TypeScript конфиг.
   - Реализовать слои UI:
     - Менеджер файлов/очередей.
     - Панель прогресса (индикаторы, общий %).
     - Детальные результаты (таблицы/модальные окна).
     - Настройки (синхронизация с backend).
   - Реализовать локализацию (i18next) и темизацию (Material UI или Tailwind + кастом).

5. **Интеграция Python backend-а с Tauri**
   - Rust-side: модуль запуска Python (`Command::new(python)`), проверка наличия venv, логирование stdout/stderr.
   - Автоматическое создание виртуального окружения и установка зависимостей при первом запуске.
   - Обработка ошибок и graceful shutdown (сигналы, timeout).
   - Поддержка офлайн-режима (проверки checksum артефактов).

6. **Сборка и деплой**
   - Настроить кроссплатформенные сборки через `tauri build`:
     - Windows/MSI.
     - macOS/DMG.
     - Linux/AppImage или `.deb` c прописанными зависимостями (включая Python runtime).
   - Сценарий упаковки Python backend-а (Embedded Python + зависимостей) внутрь Tauri-пакета.
   - Автоматизация публикации релизов (GitHub Actions + release workflow).

7. **Миграция документации и поддержка CLI**
   - Обновить README/документацию (новая архитектура, требования).
   - Обновить CLI, чтобы он обращался к core напрямую (без GUI).
   - Подготовить гайды по разработке (backend/frontend), описать процессы тестирования.

## Риски и вопросы
- **Совместимость библиотек с Python 3.14**: проверить `flet`, `pypdf`, `pillow-heif`, `hachoir`. При проблемах заменить или зафиксировать версии.
- **Пакетирование Python внутри Tauri**: нужна стратегия для Linux (например, использование `python-build-standalone` или `pyenv` + копирование env). Требует автовалидации на CI.
- **Производительность при больших пакетах**: FastAPI + asyncio должен справиться, но потребуется профилирование/кэширование.
- **Синхронизация настроек**: исключить гонки при одновременном доступе из UI и CLI.
- **Тестирование UI**: выбрать подход (Playwright, React Testing Library) и интегрировать в CI.
